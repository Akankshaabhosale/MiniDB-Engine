What am I looking at?
  • Sharding: the key is hashed (FNV-1a) to pick one of the shards, so threads working on different shards never block each other.
  • Hash table: each shard is a 101-bucket table using chaining; the bucket numbers shown are real.
  • LRU: most recently used key is on top. When a shard is full, the bottom key (dashed outline) is evicted. Capacity is deliberately tiny here.
  • TTL: expired keys are removed lazily on access and by a background thread (orange bars).
  • Durability: every write is appended to the WAL before memory changes. Crash & recover throws away all memory and rebuilds it from snapshot.db + the WAL.
